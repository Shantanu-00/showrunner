2.5The experience layerone codebase, four surfaces, zero polling

  • A statically exported Next.js App Router PWA on Firebase Hosting — so the guest app is a CDN asset with no server rendering to keep alive, and the only backend a phone talks to is api plus Firestore's own listener channel.
  • An IndexedDB outbox, not an upload form. Intent is registered first, URLs are cached against their expiry, and items left uploading by a closed tab are rewound at the start of the next drain. Closing the app mid-send is a normal event, not a lost photograph.
  • A three-tier media ladder — memory, then an IndexedDB blob store with oldest-first eviction, then a signed URL — because an authenticated image cannot be fetched with a bearer token and follow a cross-origin redirect: a preflight cannot be redirected, and no bucket CORS policy can grant a request header. So the endpoint returns the URL as JSON and the browser loads it directly. That was a real, product-wide defect, found on a phone rather than in an emulator.
  • Four surfaces, one token file — guest, wall, host console, walkthrough. And no surface personalizes a shared feed per viewer: featuring somebody is either a re-ranking every viewer sees, or it lives in that person's own private album.

2.4Build and releaseno local Docker on the build machine, by choice

Why the scene vocabulary is closed, and why that is an architecture decision rather than a lint rule: the accumulated distribution of those nine values is the world model. The count of indoor-venue against outdoor-nature across an event is what tells the system, without being told, whether it is in a ballroom or on a hillside — which is what lets a photograph of a valley be on-topic at a hill-station wedding and off-topic at a ballroom one. An open vocabulary makes that distribution uncountable (indoor, inside, hall and banquet_hall are four keys for one fact) and the arithmetic silently stops meaning anything. The signal was never in the pixels; it is in the distribution of the other photographs.

4.3Two leases, two opposite disciplines

The tick lease is mutual exclusion around an action. Acquired at the top, released at the bottom; its 5-minute TTL is purely a crash backstop. Holding it for the TTL would throttle the cadence it exists to protect — a 900 ms tick would block the next four scheduled ones while looking healthy.

The publisher lease is leadership over a resource, held for as long as the process lives and renewed on a 45-second timer. Here expiry is the failover: an instance that is scaled away stops renewing and another takes the wall over inside the TTL. Verified live: one publisher instance held nine event leases concurrently and wrote nine playlists.

Same mechanism, one file. Conflating the two would have degraded a 30-second demo cadence to one tick every five minutes.

4.4Evidence that it ran unpromptedautonomy that cannot be checked is a claim

  • platform/tickPulse — one root heartbeat document per tick: {lastTickAt, mode, caller, events, ticked, ms, ticks: Increment(1)}, written whether or not the tick found work, because a tick that found zero live events is exactly as important to record. It is what an offline smoke test waits on to prove the Scheduler fired with nobody watching.
  • A cadence a cron cannot fake. The demo event runs a 1-minute Scheduler job plus a +30 s Cloud Task interleave, so consecutive heartbeats land ~30 s apart — an interval a 1-minute cron cannot produce. Measured: :06 → :36 → :08 → :38.
  • The director's own reasoning is a document, not a dashboard — assessments, deferred ideas and permanent gaps under ledger/, plus a structured log line per stage per item. The guest-facing countdown reads a narrow projection through the API rather than through a rules exception.
  • A manual trigger exists, rate-limited and demo-only, taking the same lease so it cannot double-issue a bounty — and it is labelled on screen as an override, with the real cadence counting down above it. An unlabelled button beside a claim of autonomy contradicts your own video.

Compaction is arithmetic, not summarization. Overflowing ticks fold into a counted sentence written by code. Asking a model to summarize its own history is how a long-running agent's context becomes a story about itself — every compaction is a lossy retelling of the last one, and after fifty ticks the numbers are vibes. Counting cannot drift.

The performance instinct that reaches for a memory store is right; the mechanism is different. Not re-scanning 5,000 photographs every two minutes is solved by a materialized view inside the database — sharded coverage counters bumped in the transaction that already sets status='indexed'. That cache is transactional, shardable and auditable. Memory Bank could not do this job: it is a network call, it has no transactions, and its contents are probabilistic.

Where the director runs, and why. On Cloud Run, inside the tick, not on Agent Runtime. Every guardrail above has to be serialised by the lease the tick already holds; a remote :query would move the reasoning and leave all of them behind — one extra network hop, two places to look, identical guarantees. The importable root_agent() is still the single artifact adk deploy agent_engine would package, so the door is open, not closed. The cost is a managed reasoning-chain dashboard, and the honest replacement is named in 4.4.

Stated plainly, because it is the kind of thing worth catching before a judge does: AGENT_ENGINE_ID is empty in production, so Memory Bank is inactive and the same host free-text is read off the event document. The integration is real code on a real API and it degrades to the document silently by design — but it is not running, and it is not counted as if it were.

4.6The agent census, counted strictlythe anti-agent-washing test

A component earns the word "agent" only if it makes context-dependent judgments, or plans and chooses actions. Under that test:

2 planning agentsStory Director · Reel Director. Goal, plan, tool use, self-correction loop.
2 perception agentsCurator · Guardian. Irreducibly contextual judgment, structured verdicts, no actuation by design.
1 specialized ML workerFace Indexer. Deterministic embedding arithmetic, no LLM. Calling it an agent would be agent-washing.
Deliberate non-agentsintake · publisher · recompute_visibility · the render job · the itinerary parser (a one-shot extraction is a tool call, not an agent).

Eight LLM roles in total, counting the critic and the bounty validator. The perception agents deliberately cannot act, and that separation is the entire trust architecture.

5.2Why one job, and not a service in front of a job

  • Cloud Tasks cannot start a Cloud Run Job. Tasks speaks HTTP; a job has no URL and is started through the Run Admin API with per-execution container overrides. So the split costs an extra service, an extra identity and an extra hop — and the EDL has to be persisted on the reel document either way.
  • The consequence is stated rather than hidden: renders-queue's concurrency dial is therefore not the throttle it looks like. It could never express the real invariant anyway — "one active render per persona, per event", not a global number — so that invariant moved to a Firestore read inside the lease the Story Director already holds, with a staleness backstop because a job execution can die and leave its document in rendering forever.
  • Cost of the merge: about forty seconds of an 8-vCPU job idling on model calls and the Lyria stream — under a cent, against a whole extra deployment surface.

5.3Two quality criteria, made true instead of tested

No face crosses the frame edge. Asking the model for four floats per shot and linting them makes that a property we test. Asking it for a gesture — PUSH_IN — and deriving both rectangles from the detected face boxes makes it a property that cannot be violated, and the proof is three lines: a Ken Burns move is a linear interpolation between two axis-aligned rectangles, so each edge is linear in the interpolation parameter and attains its extremes at the endpoints; if both endpoint rectangles contain the faces' bounding box, every intermediate one does. The code guarantees the premise by walking the zoom back toward 1.0 until it holds — and when even an unzoomed 9:16 crop cannot hold a wide group line-up, the shot switches to a fitted composition: the whole photograph in frame over a blurred, drifting copy of itself. A group photo is never cropped through somebody's head to make an aspect ratio work.

No cut off the beat. The measurement is 0.000 ms, not "within ±80 ms", because the EDL only ever emits values that are already on the librosa grid: the minimum and maximum shot-length clamps step to a neighbouring beat instead of applying an offset. Nothing ever leaves the grid to have to be snapped back onto it.

5.4The consent interlock is not cosmetic

  • A published reel is served by a redirect, never by a stored URL. The reel document's videoUri is an api path that re-checks the reel's visibility on every request and 302s to a 60-minute signed URL. Not a public bucket — the object would stay fetchable after the reel is unpublished, which would make this whole interlock decorative. Not a stored signed URL either — it expires while the document still advertises it, which is a reel that plays on demo day and 404s during the judging month.
  • Playback is deliberately unauthenticated for a published reel, on the same reasoning the kiosk playlist is world-readable: a <video> element cannot send an Authorization header, and a kiosk is a television in a venue. What makes that safe is that "published" is derived — only recompute_visibility and the publish transaction write it. Downloading, by contrast, requires membership on every event: watching is not keeping.
  • Retraction runs from the one writer of visibility, and only on a public → non-public transition, because an array_contains query on every recompute would cost a query per stage completion per photograph and virtually all of those are pool → pool.
  • The renderer reads the same display_1600 derived render the gallery serves — so the zoom ceiling is 1.25, and a little softness is the price of not handing the reel renderer five hundred guests' full-resolution originals.

6.3Model Armor, in two places, because they fail differently

  • At the surface that accepts the text (the host's pasted itinerary, the bounty brief) — precise about what it rejected, and able to tell a human.
  • As an ADK plugin in front of the director models — which is what catches text that reached a prompt by any route: a tool result, a recalled memory, a caption threaded into a brief three hops from where it was typed. The surface check alone would be a list of places to remember.
  • Deliberately not attached to the perception workers. A per-photo Armor call would add a network round trip to a stage whose queue rate is calibrated, in order to inspect text the host already had checked at onboarding.
  • A deflection is a permanent failure by construction, so it takes the conservative path every worker already has — no retry storm on text that will match again.

6.7The rule that governs every demo affordance

A demo convenience is honest if it is a configuration value a real host could also set. It is a thumb on the scale if it is a code branch keyed on "this event belongs to a judge."

Under that rule the guided tour costs nothing in trust: the page, the seeded event, one-tap join, the pre-warm, the compressed timeline and the faster tick cadence are all things the product does for anyone. Two things failed the rule and were deleted rather than defended:

  • A demo-only override of the public aesthetic floor, gated on the event's class. It was a second path to a value the ordinary host-settable field already provided — and it was the only exposure logic in the system whose condition was whose event it is. Deleted; the demo event now sets the plain field any host can set.
  • A flag that auto-promoted a self-enrolling guest to VIP. A genuine branch no real host could trigger, existing only to make a visitor feel featured. It ships off.

There is no route, component, flag or query parameter named "judge mode" anywhere in the code — the label itself manufactures the suspicion that a special path exists for being looked at. The ranking-explanation overlay is ?explain=1, and it only reveals numbers the publisher already stored: it changes no query, no ordering and no visibility. The demo event's configuration is disclosed on screen, non-optionally. The consequence is binding: a later change that reintroduced a judge-conditional branch would make that disclosure the false statement.

6.4Rules grant whole documents, so the data model had to move

Firestore has no field-level read control. people/{personId} must be readable by every event member — the kiosk's uploader credit, the leaderboard's names, and the deterministic tier → vipWeight ranking all read it — and that same document was holding the face template. Any rule permitting the first would have handed every guest a copy of everyone's face.

  • The biometric moved to events/{id}/enrollments/{personId}: a collection with no allow rule at all — unreadable by every client including the host, because a console has no use for an embedding and "the host can see it" is how a biometric ends up in a screenshot.
  • people/{id}/private/* is reserved and deny-all for anything else genuinely personal — the Gemma-written taste memo lands there, not on the person document.
  • The read boundary is the event, not the sign-in. isMember(eventId) resolves a members[] custom claim minted by POST /join. It replaced a predicate that was literally "is signed in", which let anyone holding any event id read that event's wall, guest list, names and tiers. Membership rides in a claim rather than a document because a rule may not perform a get().
  • Query shape and rule shape are one design. Firestore fails an entire query when one returned document is denied rather than skipping it — so every listener carries the filters its rule requires, and the matrix runs those exact queries as those exact personas, including rows that assert dropping a filter correctly breaks.

6.5The host approves every album — no exceptions to enumerate

A live defect closed by deleting the automatic grant rather than narrowing it: enrolling with a selfie writes a held claim and grants nothing — no identity claim, no uid link, no personId on any face. Identity is granted in exactly two places: a host approval, and a magic link the album's own owner minted (where possession is the proof).

  • The face worker's auto-linker is gated on claimApproved, so a pending enrolment cannot quietly accrete an album while it waits for review — otherwise the photographs handed over would already be in a stranger's album by the time the host looked at the card.
  • A VIP match that is also ambiguous is always labelled protected_person, never ambiguous_match: the more actionable signal wins on the review card.
  • The enrolment path carries the same ban check and hourly cap as uploads, on its own window fields, so a photo burst and a selfie probe cannot hide inside each other.
  • The cost is one host tap per guest, which is what a real event looks like.

7.5Observability, stated honestlywhat exists, and what does not

There is no OpenTelemetry instrumentation and no Agent Observability dashboard in this build, because there is no Agent Runtime deployment to attach one to (4.5). Claiming a reasoning-chain span DAG would be the easiest thing on this page for a judge to falsify, so here is what exists instead — all of it queryable, and none of it a screenshot of a product page:

QuestionAnswer, and where it lives
Is the fleet acting on its own?platform/tickPulse — a rising counter and a fresh lastTickAt, written by every tick
What did the director decide, and why?ledger/directorState — assessments, the rolling window, deferred commissions, permanent gaps
What did it reject, and why?a structured log line per rejected action, carrying the guardrail that refused it
Where did this photograph spend its time?stageTimings on the media document, plus one log line per stage with ms
What has this event cost?derived on read from what was actually spent — never an incremented counter that can drift
Did anything break?the ops/ collection, sharded per worker type so no document is hot, with a severity on every alert

The trade is stated rather than buried: what a managed runtime would have granted automatically is a span DAG and a token dashboard. What running the director inside the tick buys instead is that every number which decides who gets paid lives in one file and can be checked offline, with no network and no spend. Given the choice between an observability tab and an auditable guardrail, this build took the guardrail.
